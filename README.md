# Панель управления Ollama

Локальная веб-панель (Flask) для управления Ollama на этой машине:
список/скачивание/удаление моделей, поиск GGUF-моделей на Hugging Face,
`ollama ps` с загрузкой/выгрузкой моделей из памяти, чат с моделью в модальном
окне панели (реплики пузырями, ответы как Markdown, отключаемые «размышления»,
правка и перегенерация сообщений, предпросмотр html/css/js из ответа),
журнал Ollama в реальном времени и состояние Ollama (только чтение — панель не
выполняет привилегированных команд и не требует прав root).

Панель работает на **Linux, Windows и macOS**. Источник данных о состоянии
Ollama выбирается автоматически: на Linux с systemd это юнит `ollama.service`
и `journalctl`, на Windows и macOS — процесс `ollama.exe`/`ollama` и файл
журнала (`%LOCALAPPDATA%\Ollama\server.log`, `~/.ollama/logs/server.log`).
Подробности — в разделе «Состояние и журнал Ollama на разных ОС».

Панель слушает **только loopback** (`127.0.0.1`): у неё нет аутентификации,
а доступ к локальному Ollama API и журналу из сети не нужен.

## Возможности

| Вкладка | Что делает |
|---|---|
| **Модели** | таблица установленных моделей (размер, параметры, квантизация, дата), фильтр, карточка деталей (`/api/show`), скачивание новой модели с прогрессом, удаление, предзагрузка в память («В память») и открытие чата («Чат» — модальное окно панели) |
| **Поиск на Hugging Face** | токен Hugging Face (сохранение, проверка через `whoami-v2`), поиск GGUF-моделей через публичный API `huggingface.co/api` (сортировка по загрузкам/лайкам/тренду/обновлению), список доступных квантов с размерами и кнопкой скачивания `hf.co/<repo>:<QUANT>` |
| **Загруженные (`ps`)** | модели в RAM/VRAM: размер, доля в видеопамяти, время выгрузки, автообновление, кнопки «Чат» и «Выгрузить» |
| **Логи** | журнал Ollama: последние строки, поток в реальном времени (SSE), подсветка совпадений и ошибок, очистка окна. На Linux — `journalctl -u ollama.service`, на Windows и macOS — «хвост» файла `server.log` |
| **Служба** / **Процесс** | на Linux — статус юнита (active/sub, PID, память, время старта, перезапуски); на Windows и macOS — статус процесса `ollama` (запущен, PID, память) и автозапуск. Только чтение, без прав root; управление выполняется вручную |

Шапка показывает версию Ollama, состояние Ollama (службы systemd или процесса),
число моделей и моделей в памяти и кнопку «Обновить всё». Дополнительно:
тёмная и светлая тема (кнопка в шапке, выбор запоминается в браузере),
всплывающие уведомления, закрытие окон по `Esc`.

## Чат с моделью (модальное окно)

Кнопка **Чат** (в таблице моделей или во вкладке `ps`) открывает модальное окно
панели. Окно вывода прокручивается, закрывается крестиком, кликом по фону или
`Esc`. Старый адрес `/chat?model=…` продолжает работать: он перенаправляет на
`/?chat=…` и сразу открывает это окно.

* поток токенов из `/api/chat` (SSE), кнопка **■ Стоп** прерывает генерацию;
* сообщения показываются «пузырями»: ваши реплики — **справа**, ответы модели —
  **слева**; служебные строки (баннер, вывод команд, ошибки, статистика) идут во
  всю ширину окна;
* ответы разбираются как **Markdown**: заголовки, списки (в том числе
  вложенные), таблицы, цитаты, ссылки, инлайн-код и блоки кода (с кнопкой
  **копировать**). Разметку рендерит свой модуль `static/js/markdown.js` (без
  внешних зависимостей и CDN): HTML из ответа экранируется, теги и
  `javascript:`-ссылки не выполняются. Во время генерации текст
  перерисовывается не чаще ~12 раз в секунду, чтобы поток токенов не тормозил;
* под сообщениями появляются кнопки (при наведении): **✎ Изменить** у вашего
  вопроса — текст правится на месте, всё, что было после него, отбрасывается и
  запрос уходит заново; **↻ Перегенерировать** у ответа модели — тот же вопрос
  задаётся снова; **▶ Продолжить** — дописать ответ, если модель остановилась на
  середине (лимит `num_predict`, обрыв потока, нажатый **Стоп**): прежний текст
  уходит в модель последним сообщением (`assistant`-prefill), она продолжает
  с того же места, а токены дописываются в тот же пузырь — новой реплики и
  второй записи в истории не появляется. То же делает команда `/continue`
  (продолжает последний ответ). Если модель оборвала ответ по лимиту длины, панель
  сама подскажет об этом служебной строкой;
* блоки кода **html**, **css** и **js** получают кнопку **▶ предпросмотр**:
  результат открывается в панели **справа от чата** (её же открывает кнопка
  **Предпросмотр** в шапке окна — она берёт код из последнего ответа). Панель
  разворачивается на весь экран кнопкой **⛶** (выход — `Esc`), перерисовывается
  кнопкой **⟳**, а выполнение скриптов включается флажком **скрипты** (по
  умолчанию выключено). Скрипты выключены не случайно: страница, которую рисует
  скрипт (canvas, SPA), до включения флажка выглядит пустой — подпись под панелью
  об этом предупреждает, как и о том, что внешние файлы (CDN, шрифты из интернета)
  не загружаются. Если модель прислала только CSS, стили показываются на
  служебной странице с типовыми элементами;
* у «размышляющих» моделей (qwen3, deepseek-r1 и подобных) рассуждения
  собираются в отдельный блок: пока модель «думает», он раскрыт, а с первым
  токеном ответа **сворачивается** в строку «▸ Размышления модели (N симв.)» —
  щелчок раскрывает блок обратно;
* «размышления» можно **отключить**: кнопка **Размышления: авто/выкл/вкл** в
  шапке окна (авто → выкл → вкл), селект `think` в панели **Настройки** или
  команда `/think off`. При «выкл» запрос уходит с `think: false`; значение
  по умолчанию задаётся `CHAT_THINK` (`auto`, `on`, `off`);
* после каждого ответа — статистика: токены, ток/с, время генерации и загрузки;
* панель **Настройки**: `system`, `temperature`, `top_p`, `num_ctx`,
  `num_predict`, `think`, `keep_alive` (значения запоминаются в `localStorage`);
* команды CLI: `/help`, `/clear`, `/continue`, `/system <текст|off>`,
  `/think <auto|off|on>`, `/temp 0.7`, `/top_p 0.9`, `/ctx 8192`, `/predict 512`,
  `/keep_alive 30m`, `/model имя`, `/load`, `/unload`, `/ps`, `/info`, `/bye`
  (выгружает модель и закрывает окно);
* очистка контекста кнопкой **Очистить контекст** или командой `/clear`
  забывает историю диалога **и полностью очищает окно вывода** (в нём остаётся
  только служебная строка об очистке); то же происходит при смене `system`
  (`/system …` или панель **Настройки**) — начинается новый диалог;
* бейджи в шапке окна показывают, загружена ли модель в память и когда она
  будет выгружена.

## Токен Hugging Face

Токен нужен для закрытых (`gated`) и приватных репозиториев. Задать его можно
прямо в панели — вкладка **Поиск на Hugging Face**, блок «Токен Hugging Face»:

* поле ввода + **Сохранить и проверить** — токен сохраняется в файл настроек
  панели (`data/settings.json`, права `600`) и проверяется запросом
  `GET /api/whoami-v2`; результат проверки виден в интерфейсе;
* **Удалить из панели** — поиск снова работает анонимно;
* панель использует токен для своих запросов к `huggingface.co/api`
  (поиск видит закрытые репозитории, в списке квантов видны их файлы), но
  сама Ollama о токене не знает — для `ollama pull hf.co/…` его нужно
  прописать в окружение Ollama вручную (см. ниже).

Чтобы `ollama pull hf.co/…` мог скачать закрытый репозиторий, пропишите токен
в окружение Ollama вручную — панель привилегированных команд не выполняет:

```bash
sudo systemctl edit ollama.service
# [Service]
# Environment="HF_TOKEN=hf_..."
sudo systemctl daemon-reload && sudo systemctl restart ollama.service
```

На Windows и macOS Ollama запускается как приложение, поэтому токен задают
переменной окружения пользователя (`HF_TOKEN`) и перезапускают Ollama из трея:
`setx HF_TOKEN hf_...` в cmd или «Параметры → Система → Дополнительные
параметры системы → Переменные среды».

Токен из переменной окружения `HF_TOKEN` панели тоже работает — он
используется как значение по умолчанию, если в панели ничего не сохранено
(сохранённый в панели токен имеет приоритет).

## Требования

* **Linux** — с systemd (проверено на Ubuntu 24.04, Python 3.12) либо без него
  (тогда панель читает журнал из файла);
* **Windows 10/11** — установленная Ollama (приложение в трее);
* **macOS** — установленная Ollama (приложение Ollama.app);
* Python 3.10+ (`python3-venv` на Linux, «Add Python to PATH» в установщике
  Windows);
* на Linux с systemd — доступ к журналу: пользователь входит в группу `adm` или
  `systemd-journal` (проверка: `journalctl -u ollama.service -n 5` без sudo).

Права root и sudo панели **не нужны**: управление Ollama и правка её окружения
выполняются вручную в терминале (Linux — `systemctl`, Windows/macOS — значок
Ollama в трее/меню).

## Установка и запуск

Linux и macOS:

```bash
cd ~/ollama-manage
./run.sh
```

`run.sh` при первом запуске сам создаст виртуальное окружение `venv/`,
установит зависимости из `requirements.txt` и запустит панель. Затем откройте
<http://127.0.0.1:5000>.

Windows (cmd или PowerShell):

```bat
cd C:\путь\к\ollama-manage
run.bat
```

`run.bat` делает то же самое: создаёт `venv\`, ставит зависимости и запускает
панель. Окно консоли переключается в UTF-8, чтобы кириллица в выводе не
превращалась в мусор. Если `venv` остался от прошлой версии панели, скрипт
проверит, что зависимости на месте, и при необходимости поставит их. Запускать
можно и двойным щелчком — тогда при ошибке окно остаётся открытым до нажатия
клавиши. Другой порт: `set PANEL_PORT=8080` и затем `run.bat` (или
`$env:PANEL_PORT=8080; .\run.bat` в PowerShell).

Ручной вариант:

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python app.py
```

```bat
py -3 -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe app.py
```

Пример запуска на другом порту:

```bash
PANEL_PORT=8080 ./run.sh
```

## Состояние и журнал Ollama на разных ОС

Данные о состоянии Ollama и её журнале панель берёт из того источника, который
есть в системе; бэкенд выбирается один раз при старте (`services/ollama_service.py`):

| ОС | Состояние | Журнал | Автозапуск |
|---|---|---|---|
| Linux с systemd | юнит `ollama.service`: `active/sub`, PID, память, время старта, перезапуски (`systemctl show`) | `journalctl -u ollama.service` (снимок и поток) | `unit_file_state` юнита (`enabled`/`disabled`) |
| Windows | процесс `ollama.exe` (и его раннеры `ollama_llama_server.exe`): PID, суммарная память (`tasklist`) | «хвост» файла `%LOCALAPPDATA%\Ollama\server.log` (учитываются и старые `server-N.log`) | ключи `Run` реестра (HKCU и HKLM) и папка «Автозагрузка» |
| macOS | процесс `ollama`: PID, память (`ps`) | «хвост» файла `~/.ollama/logs/server.log` | агенты `~/Library/LaunchAgents` |
| Linux без systemd | процесс `ollama`: PID, память (`ps`) | «хвост» файла журнала | не определяется (`—`) |

Порядок выбора бэкенда:

1. если задана переменная `OLLAMA_LOG_FILE` — читается файл (удобно и на Linux,
   если Ollama запущена вручную, без юнита);
2. иначе, если в системе есть `systemctl` или `journalctl` — systemd;
3. в остальных случаях — файл журнала.

Что это значит в интерфейсе:

* названия вкладок и подписи подстраиваются под ОС: на Linux — «Служба» и
  «Журнал службы», на Windows/macOS — «Процесс» и «Журнал Ollama»; строки,
  которых у процесса нет (время старта, перезапуски, `sub`-состояние юнита),
  показываются как «—», а подсказки меняются на команды для текущей ОС;
* если файл журнала не найден, вкладка «Логи» остаётся доступной, но кнопки
  обновления и потока выключены, а в окне видно подсказку с ожидаемым путём —
  достаточно запустить Ollama (или задать `OLLAMA_LOG_FILE` и перезапустить
  панель) и обновить страницу (F5): при отрисовке страницы панель снова
  проверяет, откуда читать журнал;
* поток журнала из файла (Windows, macOS и Linux без systemd) — это `tail -f`,
  реализованный на Python (`services/logtail.py`) и запускаемый отдельным
  процессом: он корректно завершается при закрытии вкладки, как `journalctl -f`
  на Linux.

| Переменная | По умолчанию | Назначение |

| `OLLAMA_SERVICE` | `ollama.service` | имя systemd-юнита (используется на Linux с systemd) |
| `OLLAMA_PROCESS_NAME` | `ollama.exe` (Windows) / `ollama` | имя процесса Ollama для Windows/macOS и Linux без systemd |
| `OLLAMA_LOG_FILE` | — | путь к файлу журнала Ollama; если задан, панель читает журнал из файла даже при наличии systemd |
| `PANEL_HOST` | `127.0.0.1` | адрес прослушивания панели |
| `PANEL_PORT` | `5000` | порт панели |
| `PANEL_DEBUG` | `0` | включить режим отладки Flask (`1`/`true`/`yes`/`on`) |
| `HTTP_TIMEOUT` | `10` | таймаут обычных запросов к Ollama, с |
| `PULL_TIMEOUT` | `3600` | таймаут чтения потока `/api/pull`, с |
| `CHAT_TIMEOUT` | `600` | таймаут чтения потока `/api/chat`, с |
| `LOAD_TIMEOUT` | `600` | таймаут загрузки модели в память, с |
| `JOURNAL_LINES_DEFAULT` | `200` | сколько строк журнала отдавать по умолчанию (и для `journalctl`, и для файла) |
| `JOURNAL_LINES_MAX` | `5000` | верхняя граница параметра `lines` |
| `HF_API_BASE` | `https://huggingface.co/api` | базовый адрес API Hugging Face |
| `HF_TIMEOUT` | `20` | таймаут запросов к Hugging Face, с |
| `HF_SEARCH_LIMIT_DEFAULT` | `20` | сколько результатов поиска запрашивать по умолчанию |
| `HF_SEARCH_LIMIT_MAX` | `50` | верхняя граница количества результатов |
| `CHAT_KEEP_ALIVE` | `5m` | сколько держать модель в памяти после ответа чата |
| `PRELOAD_KEEP_ALIVE` | `30m` | `keep_alive` по умолчанию для кнопки «В память» |
| `CHAT_THINK` | `auto` | размышления моделей: `auto` (как решит модель), `off` (`think=false`), `on` (`think=true`) |
| `HF_TOKEN` | — | токен Hugging Face по умолчанию (сохранённый в панели имеет приоритет) |
| `PANEL_DATA_DIR` | `./data` | каталог настроек панели |
| `PANEL_SETTINGS_FILE` | `./data/settings.json` | файл настроек панели (в нём лежит токен HF, права `600`) |

## HTTP API панели

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/` | интерфейс панели (`?chat=модель` сразу открывает окно чата) |
| GET | `/chat?model=…` | редирект на `/?chat=…` (совместимость со старым адресом окна чата) |
| GET | `/api/overview` | сводка: состояние Ollama (служба или процесс), версия Ollama, счётчики, ошибки |
| GET | `/api/models` | список установленных моделей |
| GET | `/api/models/details?name=…` | детали модели (`/api/show`) |
| POST | `/api/models/pull` | скачивание модели, SSE-поток прогресса |
| POST | `/api/models/load` | загрузка модели в память (`keep_alive`) |
| POST | `/api/models/delete` | удаление модели |
| POST | `/api/models/unload` | выгрузка модели из памяти |
| GET | `/api/ps` | модели, загруженные в память |
| GET | `/api/hf/search?q=…&sort=&limit=` | поиск GGUF-моделей на Hugging Face (с токеном видны закрытые репозитории) |
| GET | `/api/hf/quants?repo=user/name` | кванты (GGUF-файлы) в репозитории |
| GET | `/api/settings` | состояние настроек панели: токен HF (без самого токена) |
| POST | `/api/settings/hf-token` | сохранить токен HF (`{"token": "hf_…"}`, пустой — удалить) и проверить его |
| POST | `/api/chat` | ответ модели, SSE-поток событий `start` / `thinking` / `chunk` / `done` / `error` |
| GET | `/api/logs?lines=N` | снимок журнала Ollama (`journalctl` или файл) |
| GET | `/api/logs/stream?lines=N` | поток журнала (`journalctl -f` или «хвост» файла) через SSE |
| GET | `/api/service/status` | состояние Ollama: юнит systemd или процесс (только чтение) |

Тело POST-запросов — JSON: `{"name": "llama3.2:3b"}` (для загрузки в память
можно добавить `"keep_alive": "30m"`), для чата —
`{"model": "…", "messages": [{"role": "user", "content": "привет"}],
"options": {"temperature": 0.7}, "keep_alive": "5m", "think": false}`
(`think` необязателен: `false` — без размышлений, `true` — с ними, отсутствие —
решает модель).

Примеры:

```bash
curl -s http://127.0.0.1:5000/api/overview
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"name":"llama3.2:3b"}' http://127.0.0.1:5000/api/models/pull
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"name":"llama3.2:3b","keep_alive":"30m"}' http://127.0.0.1:5000/api/models/load
curl -s 'http://127.0.0.1:5000/api/hf/search?q=qwen2.5%207b&sort=downloads&limit=5'
curl -s 'http://127.0.0.1:5000/api/hf/quants?repo=bartowski/Qwen2.5-7B-Instruct-GGUF'
curl -s http://127.0.0.1:5000/api/settings
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"token":"hf_…"}' http://127.0.0.1:5000/api/settings/hf-token
curl -N -X POST -H 'Content-Type: application/json' \
     -d '{"model":"qwen3:8b","messages":[{"role":"user","content":"привет"}],"think":false}' \
     http://127.0.0.1:5000/api/chat
curl -N 'http://127.0.0.1:5000/api/logs/stream?lines=50'
curl -s http://127.0.0.1:5000/api/service/status
```

Коды ответов: `400` — некорректный запрос (в том числе неверный формат токена
HF и неизвестное значение `think`), `502` — ошибка Ollama/`systemctl`/`journalctl`/
чтения файла журнала/Hugging Face, `404` — неизвестный маршрут.

## Безопасность

* Панель **не выполняет привилегированных команд и не требует прав root**:
  запуск, остановка и перезапуск Ollama, а также правка её окружения делаются
  вручную в терминале (Linux — `systemctl`, Windows/macOS — значок Ollama в
  трее/меню). Все изменяющие операции панели идут через REST API Ollama
  (скачивание, удаление и загрузка моделей в память, чат).
* Из системных команд панель выполняет только **читающие**: `systemctl show` /
  `journalctl` (Linux с systemd), `tasklist` (Windows), `ps` (macOS и Linux без
  systemd) — и всегда без оболочки (`shell=False`), с фиксированным набором
  аргументов. На Windows вспомогательные команды запускаются с флагом
  `CREATE_NO_WINDOW`, чтобы не мигало окно консоли.
* Панель по умолчанию слушает `127.0.0.1` — из сети недоступна. Меняйте
  `PANEL_HOST` только осознанно: у панели нет аутентификации.
* Предпросмотр html/css/js из ответа модели работает **в браузере**: документ
  собирается в `srcdoc` и грузится в `iframe` с `sandbox` **без**
  `allow-same-origin` (у предпросмотра свой origin — доступа к панели, её DOM и
  `localStorage` нет) и с CSP внутри документа (`default-src 'none'`,
  `connect-src 'none'`, `form-action 'none'`): сеть, внешние ресурсы и отправка
  форм запрещены, а скрипты не выполняются, пока пользователь не включит флажок
  «скрипты». CSP вшивается и в готовую страницу модели (мета ставится в её
  `<head>`), иначе режим «скрипты выключены» держался бы только на `sandbox`.
  Так как флаги `sandbox` действуют лишь при следующей загрузке документа, перед
  сменой прав кадр выгружается и документ грузится заново. Код из ответа модели
  никогда не исполняется на сервере — панель только отдаёт статику.
* Токен Hugging Face хранится в `data/settings.json` с правами `600` и никогда
  не отдаётся браузеру (интерфейс видит только подсказку вида `hf_abc…1234`).
  Каталог `data/` добавлен в `.gitignore`. Если токен нужно передать самой
  Ollama (`ollama pull hf.co/…`), пропишите его в окружение Ollama вручную
  (Linux — `systemctl edit ollama.service`, Windows/macOS — переменная
  окружения `HF_TOKEN` и перезапуск Ollama); панель это за вас не делает.
* Flask-сервер разработки подходит только для локального использования. Если
  нужно вывести панель в сеть — поставьте перед ней reverse-proxy с
  аутентификацией и HTTPS.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| Журнал пуст, в логе панели «нет доступа к журналу» | нет доступа к `journalctl`: добавьте пользователя в группу `adm` или `systemd-journal` и перелогиньтесь |
| Вкладка «Логи»: «Журнал Ollama не найден (…)» | панель читает файл журнала, а его нет: запустите Ollama или укажите путь переменной `OLLAMA_LOG_FILE` |
| Вкладка «Логи» показывает не то, что ожидалось | журнал читается из файла, хотя есть systemd: уберите `OLLAMA_LOG_FILE` (переменная переключает бэкенд на файл) |
| «Не удалось подключиться к Ollama» | Ollama не запущена или `OLLAMA_HOST` неверен — на Linux проверьте `systemctl status ollama`, на Windows/macOS — значок Ollama в трее |
| На вкладке «Служба»/«Процесс» вместо времени старта и перезапусков «—» | это нормально для Windows/macOS: у обычного процесса таких сведений нет |
| Статус процесса «не запущен», хотя Ollama работает | изменилось имя процесса — задайте его переменной `OLLAMA_PROCESS_NAME` |
| Скачивание зависает | большие модели качаются долго; прогресс идёт в блоке под полем ввода. Таймаут потока — `PULL_TIMEOUT` |
| «Нет соединения с huggingface.co» | нет доступа в интернет или прокси: задайте `HF_API_BASE`/`HF_TIMEOUT`, проверьте `curl -s https://huggingface.co/api/models?limit=1` |
| В списке HF нет нужного репозитория | поиск идёт только по моделям с тегом `gguf`; попробуйте другой запрос или укажите `hf.co/user/repo:QUANT` в поле «Скачать модель» на вкладке «Модели» |
| Скачивание gated-модели падает с 401/403 | нужен токен: задайте его на вкладке «Поиск на Hugging Face» (блок «Токен Hugging Face») — панель будет видеть закрытые репозитории. Чтобы токен получил `ollama pull`, пропишите `HF_TOKEN` в окружение Ollama вручную (см. раздел «Токен Hugging Face») |
| «Токен не принят Hugging Face» при сохранении | токен истёк или у него нет прав `read`: создайте новый на <https://huggingface.co/settings/tokens> |
| Модель отвечает пустой строкой или только размышлениями | это reasoning-модель: нажмите **Размышления: выкл** (`/think off`, `think=false`), увеличьте `num_predict` (`/predict 2048`) или смените модель |
| Модель «затыкается» на середине ответа | чаще всего упёрлась в лимит длины (`done_reason=length`, в статистике это видно): нажмите **▶ Продолжить** у ответа или отправьте `/continue` — ответ уйдёт в модель последним сообщением и она допишет его с того же места, в тот же пузырь. Либо поднимите лимит: `/predict 2048` или панель **Настройки**. Если поток оборвался по таймауту (`CHAT_TIMEOUT`) или вы нажали **Стоп**, кнопка работает так же |
| «… does not support thinking» | у модели нет размышлений, а запрос ушёл с `think=true`: переключите «Размышления» в «авто» или «выкл» |
| Чат «висит» на первом ответе | модель загружается в память: следите за бейджем «в памяти»; таймаут потока — `CHAT_TIMEOUT` |
| Порт занят | запустите с другим портом: `PANEL_PORT=8080 ./run.sh` (Windows: `set PANEL_PORT=8080` и `run.bat`) |
| `run.bat`: «python не является внутренней или внешней командой» | Python не в PATH: переустановите его с галочкой «Add Python to PATH» либо запускайте панель вручную из `venv\Scripts\python.exe` |
| `run.bat`: кириллица в выводе выглядит как мусор | старые версии Windows плохо поддерживают UTF-8 в консоли: запустите `chcp 65001` вручную или используйте Windows Terminal |

## Автозапуск панели (необязательно)

```ini
# ~/.config/systemd/user/ollama-panel.service
[Unit]
Description=Flask-панель управления Ollama
After=network-online.target ollama.service

[Service]
WorkingDirectory=%h/ollama-manage
ExecStart=%h/ollama-manage/venv/bin/python %h/ollama-manage/app.py
Restart=on-failure

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now ollama-panel.service
journalctl --user -u ollama-panel -f
```

Привилегированных действий у панели нет, поэтому юнит-режим работает без
ограничений: Ollama управляйте через `systemctl` в терминале.

Windows: создайте ярлык на `run.bat` и положите его в папку автозагрузки
(`Win+R` → `shell:startup`) — панель будет подниматься при входе в систему.
Если окно консоли не нужно, в свойствах ярлыка выберите «Свернутое в значок»
или запускайте через «Планировщик заданий» с флажком «Скрыть окно».

macOS: то же самое через «Системные настройки → Основные → Элементы входа»
(добавьте `run.sh` или заранее созданный `.command`-файл).
